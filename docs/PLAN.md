## 2. 기술 스택 (빠른 개발 + 에셋 없이 시작)

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + TypeScript | 빠른 HMR, Vercel 기본 지원 |
| 3D | Three.js | 경량, 블록 캐릭터를 코드로 생성 가능 |
| 물리 | 자체 간이 충돌(지면 레이캐스트 + AABB/원기둥) | 아케이드 감성엔 충분, 번들 작음 |
| 캐릭터·소품 | **코드로 조립하는 블록 모델**(BoxGeometry 파츠) | 외부 3D 에셋·라이선스 문제 없음, Codex에 일괄 위임 쉬움 |
| UI | HTML/CSS 오버레이(프레임워크 없음) | 퀴즈·대화창을 빠르게, 한글 폰트 품질 |
| 효과음 | ZzFX(초소형 절차적 SFX, MIT) 프리셋 | 파일 없이 코드로 수십 개 생성 |
| 배경음 | WebAudio 자체 스텝 시퀀서(악보를 JSON으로) | 챕터별 BGM을 데이터로 일괄 생성 |
| 저장 | localStorage (세이브 슬롯 3개) | 서버 불필요 |
| 입력 | 키보드+마우스 / 터치(가상 조이스틱+큰 버튼) | 아이는 태블릿을 많이 씀 |
| 테스트 | Vitest (학습 문제 생성기·저장·진행 로직) | Codex 작업 검증용 |

## 3. 게임 구조

### 3-1. 월드
- **에게해 허브 맵**: 바다 위를 배로 자유 항해(오픈월드). 섬은 스토리 순서대로 열리고, 이미 연 섬은 언제든 재방문.
- 회상 구간(3~11장)은 '기억의 바다'(노을·꿈 색감), 현재 구간(1·2·12~17장)은 맑은 바다로 색감을 나눔.
- 섬마다: 탐험 구역 → 목표(구출·수집·퍼즐) → 보스/클라이맥스 → 이야기 카드.
- 사이드 콘텐츠: **아테나 부엉이 신전**(섬마다 1~3개, 하루 퀴즈), 숨은 보물상자, 올리브잎 코인으로 아바타 꾸미기(투구·망토·방패 색 — 로블록스식 커스터마이즈).

### 3-2. 플레이어
- 이동/점프/구르기(회피), 검 3연타, 방패 막기, 9장 이후 **활**(16장 활쏘기 복선).
- 체력 하트 5개, 실패 시 가까운 체크포인트로 즉시 부활(아이용 저스트레스).
- 적은 쓰러지면 **별가루로 사라짐**(유혈 없음).

### 3-3. 학습 시스템 ("아테의 지혜")
학습이 전투 흐름을 끊지 않도록 4가지 방식으로 배치:
1. **지혜의 문**: 길을 막은 석문, 문제를 풀면 열림(필수, 챕터당 2~4개).
2. **보스 약점 페이즈**: 보스가 지치면 퀴즈 → 정답 시 큰 데미지/기절.
3. **NPC 대화 선택지**: 예절 문제는 대부분 여기(올바른 말·행동 고르기).
4. **부엉이 신전**: 선택형 보너스, 코인·꾸미기 아이템 보상.

과목별 학년 수준(설정에서 1·2·3학년 선택, 정답률에 따라 자동 미세조정):

| 과목 | 1학년 | 2학년 | 3학년 | 문제 형식 |
|---|---|---|---|---|
| 영어단어 | 그림↔단어(동물·색·숫자) 3글자 내외 | 자연·가족·몸, 철자 빈칸 1개 | 문장 속 단어, 철자 조합 | 그림 4지선다, 철자 방울 모으기 |
| 한자 | 8급 기초(一~十, 日月火水木金土) | 8급 전체(50자) | 7급 일부, 한자어(家族·山水) | 뜻·음 고르기, 한자 찾기 |
| 수학 | 20 이내 덧·뺄셈 | 두 자리 덧·뺄셈, 곱셈구구 2·5단 | 세 자리 덧·뺄셈, 곱셈구구 전체, 나눗셈 기초 | 숫자패드, 4지선다, 개수 세기 |
| 시계 | 정각·30분 읽기 | 5분 단위, 몇 시 몇 분 | 1분 단위, 걸린 시간(몇 시간/몇 분 후) | 시계 읽기, **바늘 드래그로 맞추기** |
| 예절 | 인사·감사·사과 | 차례 지키기, 식사 예절, 공공장소 | 존댓말, 손님 예절, 정직·약속 | 상황 장면 + 선택지 |

- 오답: 벌점 없음 → 아테의 힌트 → 같은 문제 나중에 다시(라이트너 복습 상자 3칸).
- **보호자 모드**(설정 → 암호 대신 간단한 곱셈 문제로 진입): 과목별 정답률, 자주 틀린 단어, 학년 설정, 1회 플레이 시간 제한(20/30/40분 알림).

## 4. 코드 구조 (병렬 작업을 위한 경계)

```
src/
  core/        엔진 루프, 입력, 카메라, 충돌, 저장, 이벤트 버스        ← Claude
  player/      플레이어 컨트롤러, 전투, 애니메이션                     ← Claude
  enemies/     적 AI 베이스 + 보스 패턴                                ← Claude(베이스) / 함께(보스)
  world/       허브 바다, 섬 로더, 지형 생성, 소품 배치                 ← Claude(로더) / Codex(섬 데이터)
  models/      블록 캐릭터·소품 빌더 (순수 함수: () => THREE.Group)    ← Codex 통째로
  learning/    문제 엔진, 생성기(수학·시계), 복습 상자, 퀴즈 UI         ← Claude(엔진·UI) / Codex(생성기·데이터)
  story/       챕터 진행 상태머신, 대화 시스템                          ← Claude
  audio/       SFX 프리셋, BGM 시퀀서, 곡 데이터                        ← Codex 통째로(인터페이스는 Claude)
  ui/          HUD, 메뉴, 보호자 모드, 터치 컨트롤                      ← Claude / 함께
data/
  learning/    english.json, hanja.json, manners.json                   ← Codex 통째로
  chapters/    ch01.json … ch17.json (대사·목표·문제 배치)              ← Codex 통째로(STORY.md 기반)
  islands/     섬 레이아웃 데이터                                        ← Codex 초안 → 함께 다듬기
```

**핵심 원칙**: Phase 0에서 Claude가 `src/types/contracts.ts`(데이터 스키마·모듈 인터페이스)를 먼저 확정 → 그 뒤 Codex 일괄 작업과 Claude 엔진 작업이 **서로 다른 폴더에서 동시에** 진행. 충돌 없음.

| **P3 귀향** | 12~17장, 엔딩, 활 시스템, 이타카 오픈월드 | Claude + 함께 | |

## 6. Codex 협업 가이드

### 6-1. 통째로 맡길 것 (계약만 맞으면 독립적으로 끝나는 일)

- **A3** 효과음 프리셋 40종 + BGM 10곡 데이터 + 시퀀서
- **A4** 블록 모델 빌더 (주인공·NPC 15·적 10·보스 9·소품 30)
- **B1** 17개 챕터 대사/목표 JSON (STORY.md 그대로 변환)
- **B2** 섬 레이아웃 초안 데이터
- P4의 개별 버그 수정 이슈

### 6-2. 함께 할 것 (엔진 감각·재미 판단이 필요한 일)
- 보스 패턴 9종: Claude가 베이스·첫 보스(폴리페모스)를 만들고 패턴 템플릿 확정 → 나머지 보스는 Codex가 템플릿 복제 구현 → Claude가 리뷰·튜닝
- 섬 레이아웃: Codex 초안 → 실제 플레이 후 Claude가 동선·난이도 조정
- 밸런스·플레이테스트 피드백 반영

### 6-3. Claude가 직접 할 것 (구조를 결정하는 일)
- 엔진 코어, 플레이어 조작감, 카메라, 충돌, 챕터 상태머신, 학습 엔진·퀴즈 UI, 통합, 배포

### 6-4. Codex 모델·추론 수준 추천
기본은 말씀하신 대로 **Astra High**로 두고, 일의 성격에 따라 이렇게 나누면 속도와 품질이 균형 잡힙니다.

| 작업 | 추천 | 이유 |
|---|---|---|
| A2 생성기+테스트, A4 블록 모델, 보스 패턴 구현, 버그 수정 | **Astra High** (기본) | 로직·좌표·엣지케이스 판단이 필요 |
| A1 학습 데이터, B1 챕터 대사 JSON | **Medium 수준**(같은 모델 추론 낮춤 또는 빠른 경량 모델) | 분량이 많고 규칙이 명확 — 속도가 중요. 단, 학년 수준 검수는 마지막에 High로 1회 리뷰 |
| A3 사운드 | **Astra High** | 음악 데이터는 화성·리듬 규칙 실수가 잦음 |
| B2 섬 레이아웃 초안 | **Medium** | 초안이고 어차피 함께 다듬음 |
| 대규모 리팩터링·성능 문제 추적(필요 시) | 사용 가능한 최고 추론 단계 | 원인 추적이 길어지는 작업에만 |
